# Веб-сервис расчета времени отклика веб-приложения (`system_components`)

## 1. Таблицы базы данных

### 1.1. Таблица `users` (Пользователи)
| Поле | Тип данных | Ограничения | Описание |
|---|---|---|---|
| `id` | `serial / uint` | `PRIMARY KEY` | Уникальный идентификатор пользователя |
| `login` | `varchar(50)` | `UNIQUE, NOT NULL` | Логин пользователя |
| `password` | `varchar(255)` | `NOT NULL` | Пароль пользователя (скрыт при JSON-сериализации) |

### 1.2. Таблица `system_components` (Компоненты системы / Услуги)
| Поле | Тип данных | Ограничения | Описание |
|---|---|---|---|
| `id` | `serial / uint` | `PRIMARY KEY` | Уникальный идентификатор компонента |
| `name` | `varchar(100)` | `NOT NULL` | Название компонента (заполняется на шаге «Далее») |
| `description` | `text` | `NULL` | Описание компонента (заполняется при публикации) |
| `status` | `varchar(20)` | `NOT NULL` | Статус записи: `draft`, `published`, `deleted` |
| `image_url` | `varchar(255)` | `NOT NULL` | Ссылка на изображение в хранилище MinIO |
| `video_url` | `varchar(255)` | `NOT NULL` | Ссылка на демонстрационное видео в хранилище MinIO |
| `priority` | `integer` | `NULL` | Приоритет обработки запроса (заполняется при публикации) |
| `grouping` | `varchar(50)` | `NULL` | Архитектурный слой / группировка (`Бэкенд`, `Кэш`, `БД`) |
| `created_at` | `timestamp` | `NOT NULL` | Дата и время создания черновика |
| `creator_id` | `integer / uint` | `NOT NULL, FK -> users(id)` | ID пользователя-создателя |
| `formed_at` | `timestamp` | `NULL` | Дата и время публикации компонента |

### 1.3. Таблица `component_likes` (Лайки компонентов, связь М:М)
| Поле | Тип данных | Ограничения | Описание |
|---|---|---|---|
| `id` | `serial / uint` | `PRIMARY KEY` | Уникальный идентификатор записи лайка |
| `user_id` | `integer / uint` | `NOT NULL, FK -> users(id)` | ID пользователя, поставившего лайк |
| `component_id` | `integer / uint` | `NOT NULL, FK -> system_components(id)` | ID компонента, которому поставлен лайк |

## 2. Методы REST API (10 методов)

### Домен услуги (`system-components`)
1. **`GET /api/system-components`** — получение списка опубликованных компонентов с фильтрацией по слою (`?groups=Кэш` или `?grouping=Кэш`). Возвращает массив карточек с количеством лайков `likes_count` и признаком `is_creator` (`0` или `1` — совпадает ли создатель с текущим пользователем, нужно для отображения кнопки удаления).
2. **`GET /api/system-components/feed`** — получение одной карточки опубликованного компонента для ленты (без параметров — первая запись; с параметрами `?id=1&next=true` — следующая по порядку запись в БД). Возвращает объект с полями `is_liked` (`0` или `1` — лайкнул ли текущий пользователь) и `is_creator` (`0` или `1`).
3. **`GET /api/system-components/draft`** — получение полей активного черновика текущего пользователя (без указания `id` в URL, не более 1 записи).
4. **`POST /api/system-components`** — создание черновика компонента (кнопка «Далее»). Принимает `multipart/form-data`: поле `name` и файлы `image` и `video`. Сохраняет файлы в бакет MinIO `system-components` с латинскими именами (`component_<id>_img.png`, `component_<id>_video.mp4`).
5. **`PUT /api/system-components/:id`** — публикация черновика (кнопка «Опубликовать»). Переводит запись из статуса `draft` в `published`, устанавливает `formed_at` и заполняет поля `description`, `grouping`, `priority`.
6. **`DELETE /api/system-components/:id`** — мягкое удаление (`soft delete`) компонента текущего пользователя (перевод статуса в `deleted`).
7. **`POST /api/system-components/:id/like`** — постановка (`{"like": 1}`) или отмена (`{"like": 0}`) лайка компоненту от имени текущего пользователя.

### Домен пользователя (`users`)
8. **`POST /api/users/register`** — регистрация нового пользователя (`login`, `password`).
9. **`POST /api/users/login`** — аутентификация пользователя (заглушка для ЛР-4).
10. **`POST /api/users/logout`** — деавторизация пользователя (заглушка для ЛР-4).
